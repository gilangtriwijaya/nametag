File output nametag tidak dapat ditulis karena:

| Detail | Value |
|--------|-------|
| File | `public/nametag/front/17.png` |
| Owner | `root:root` |
| Permissions | `644 (-rw-r--r--)` |
| Process User | `deploy` (PHP-FPM) |
| Problem | File dimiliki root, hanya readable oleh deploy |

**Kapan terjadi**: Feb 6, 2026 02:58 (mungkin dihasilkan oleh proses root pada saat itu)

### 2. Activity Log Not Created (Secondary Issue)

Meskipun process gagal, **tidak ada entry di activity_log**. Root cause:

#### Call Flow Analysis

**Path A: NametagOrchestrator (memiliki activity log)**
```
NametagOrchestrator::generateSingle()
  ↓
  ├─ renderForEmployee() [try-catch, log exception]
  │   └─ NametagRenderService::renderFront/renderBack()
  │
  └─ activity('nametag')->performedOn($employee)->log() ← ACTIVITY LOG DIBUAT DISINI
```

**Path B: RenderSingleNametagJob (TIDAK punya activity log) ⚠️**
```
RenderSingleNametagJob::handle()
  ↓
  └─ $renderer->renderFront($e, $tplFront) ← Direct call BYPASS orchestrator
      └─ NametagRenderService::renderFront()
         └─ imagepng() → ERROR
         
      ❌ NO ACTIVITY LOG CREATED
      ❌ Only application log entry (nametag.render_exception)
```

**Alasan**: Ketika menggunakan queue worker untuk background rendering,  job memanggil `NametagRenderService` secara langsung tanpa melalui `NametagOrchestrator`. Class `NametagOrchestrator` adalah satu-satunya yang membuat activity log entries.

## Solutions

### Quick Fix: File Ownership (Immediate)

```bash
# Fix file ownership for affected files
chown deploy:deploy public/nametag/front/17.png
chown deploy:deploy public/nametag/front/16.png
chown deploy:deploy public/nametag/front/19.png
chown deploy:deploy public/nametag/front/271.png

# OR fix entire nametag directory structure
chown -R deploy:deploy public/nametag/
chmod -R 755 public/nametag/*/
chmod -R 644 public/nametag/*/*
```

### Permanent Fix: Activity Log in Job (Architectural)

**Current Issue**: `RenderSingleNametagJob` doesn't create activity logs on failure

**Options**:

#### Option 1: Use NametagOrchestrator in Job
```php
// In RenderSingleNametagJob::handle()
$orchestrator = app(NametagOrchestrator::class);
$result = $orchestrator->generateSingle($e, $force);
// Now activity logs are automatically created
```

#### Option 2: Add Activity Logging to Job Handler
```php
// After render in RenderSingleNametagJob::handle()
if (!$okF || !$okB) {
    try {
        if (!$okF) {
            activity('nametag')
                ->performedOn($e)
                ->event('render_front')
                ->withProperties(['ok' => false, 'via' => 'job'])
                ->log('Render front gagal (via job)');
        }
        if (!$okB) {
            activity('nametag')
                ->performedOn($e)
                ->event('render_back')
                ->withProperties(['ok' => false, 'via' => 'job'])
                ->log('Render back gagal (via job)');
        }
    } catch (\Throwable $e) {
        Log::warning('Failed to log activity for failed job render');
    }
}
```

#### Option 3: Catch Exception at Top Level
```php
// In RenderSingleNametagJob::handle()
try {
    // ... existing render logic
} catch (\Throwable $t) {
    activity('nametag')
        ->event('render_exception')
        ->withProperties(['employee_id' => $this->employeeId, 'error' => $t->getMessage()])
        ->log('Render exception di job: ' . $t->getMessage());
    throw;
}
```

## Prevention Measures

1. **File Permission Management**:
   - Ensure all rendered files are created with `deploy:deploy` ownership
   - Add periodic permission audit/fixup in maintenance commands
   - Set umask in PHP-FPM to ensure correct permissions

2. **Activity Log Completeness**:
   - All render operations (synchronous + async) should log to activity_log
   - Failed operations MUST have activity log entries for debugging
   - Use middleware/wrapper pattern to ensure consistency

3. **Error Handling**:
   - Wrap ALL render calls with activity logging
   - Log failures at the point where error occurs, not just in exception handler
   - Consider circuit breaker for repeated failures
